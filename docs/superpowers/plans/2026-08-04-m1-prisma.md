> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>

**Goal:** Give `apps/api` a real PostgreSQL-backed data layer — Prisma schema matching the spec's data model,
an initial migration, a Fastify plugin that exposes a connected Prisma client to every route, and a seed
script producing two demo accounts with realistic shipment history — so M2 (auth) and M3 (shipments CRUD)
have a working database to build against.

**Architecture:** `apps/api/prisma/schema.prisma` is the single source of truth for the data model (mirrors
spec Section 5 verbatim: `User`, `Shipment`, `MovementEvent`, `Role`, `ShipmentStatus`). A `prismaPlugin`
(Fastify plugin, `fastify-plugin`-wrapped) instantiates one `PrismaClient`, connects it on app boot, decorates
`app.prisma`, and disconnects it in Fastify's `onClose` hook — every later module (auth, shipments, webhooks)
reads `request.server.prisma` rather than importing its own client. Password hashing lives in
`apps/api/src/lib/password.ts` using Node's built-in `crypto.scrypt` (no new dependency) because the seed
script needs to store a `passwordHash` for demo users now, even though the full auth flow lands in M2 — M2
will import and reuse `hashPassword`/`verifyPassword` from this same file rather than redefining hashing.

**Tech Stack:** Prisma 7 (`prisma`, `@prisma/client`, `@prisma/adapter-pg`, `pg`), PostgreSQL 16 (already
running via `docker-compose.yml` from M0), `dotenv` for local env loading, `fastify-plugin`, Node's built-in
`node:crypto` for password hashing.

> **Post-execution note:** this plan was originally written assuming Prisma 6 conventions (datasource
> `url = env("DATABASE_URL")` inline in `schema.prisma`, `PrismaClient` connecting straight from that env
> var, seed command declared in `package.json`'s `"prisma"` field). The installed version was Prisma 7,
> which changed all three: connection config moved to a new `apps/api/prisma.config.ts` file, `PrismaClient`
> now requires an explicit driver adapter (`@prisma/adapter-pg`) passed to its constructor, and the seed
> command is declared in `prisma.config.ts`'s `migrations.seed`, not `package.json`. The task steps below
> already reflect what was actually built (post-execution edit), not the original Prisma-6-shaped draft.

// apps/api/src/lib/password.ts
import { randomBytes, scrypt as scryptCallback, timingSafeEqual } from 'node:crypto';
import { promisify } from 'node:util';

const scrypt = promisify(scryptCallback);
const KEY_LENGTH = 64;

export async function hashPassword(password: string): Promise<string> {
  const salt = randomBytes(16).toString('hex');
  const derivedKey = (await scrypt(password, salt, KEY_LENGTH)) as Buffer;
  return `${salt}:${derivedKey.toString('hex')}`;
}

export async function verifyPassword(password: string, storedHash: string): Promise<boolean> {
  const [salt, key] = storedHash.split(':');
  if (!salt || !key) {
    return false;
  }

  const keyBuffer = Buffer.from(key, 'hex');
  const derivedKey = (await scrypt(password, salt, KEY_LENGTH)) as Buffer;

  return keyBuffer.length === derivedKey.length && timingSafeEqual(keyBuffer, derivedKey);
}
```

// apps/api/src/plugins/prisma.ts
import { PrismaPg } from '@prisma/adapter-pg';
import { PrismaClient } from '@prisma/client';
import fp from 'fastify-plugin';
import type { FastifyInstance } from 'fastify';

declare module 'fastify' {
  interface FastifyInstance {
    prisma: PrismaClient;
  }
}

export const prismaPlugin = fp(async (app: FastifyInstance) => {
  const adapter = new PrismaPg({ connectionString: process.env['DATABASE_URL'] });
  const prisma = new PrismaClient({ adapter });
  await prisma.$connect();

  app.decorate('prisma', prisma);

  app.addHook('onClose', async (instance) => {
    await instance.prisma.$disconnect();
  });
});
```
